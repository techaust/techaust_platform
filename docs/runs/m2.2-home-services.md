**Goal:** the owner sees and approves the home page, and the service-page template, before the rest is built.

**First step:** load `frontend-design:frontend-design` (and `cloudflare:web-perf`, since LCP, fonts and JS budget are acceptance criteria). List the skills in the report.

**Branch:** `feat/m2.2-home-services` from `main` (this branch: it holds this run file), own worktree. Build the preview as **real Astro components and sections** in `apps/web`, so the approved preview becomes the build. Preview pages are dev-only, injected the same way as M2.1's (`astro.config.mjs`, `src/preview/*.astro`; never built).

**Pages (preview only, `noindex`):**
- `/preview/home`: the full home page inside the shell, with the **final copy from 07 §3 word for word** (meta, hero, who we help, what we do (6 cards, each with a "from" price), how we work (4 steps), care-plans teaser, pricing anchors, recent work (the no-case-studies fallback), FAQ (5), final CTA band).
- `/preview/service`: the AI Document Automation page (07 §4.5, template 04 §3.2: hero → problem → what you get → how it works → pricing and engagement → tech → proof (omitted: no case study or sample for S9) → FAQs → related → CTA band), including its **illustrative workflow diagram** labelled with the 07 §2.4 "Illustrative example" text.

**Prices in the preview:** real "from" prices from the seed catalogue (`packages/db/src/seed/catalogue.ts`, owner-approved in Phase 2), read through **one small helper** in `apps/web/src/lib/` (e.g. `priceOf("S1")`, plus the S16 tier lines for `{{price:S16-essential}}`), rendered only by `PriceTag` / `@techaust/core` formatting. No amount typed into a template (the WEB-G-07 build check). The builder later puts the snapshot schema and the `{{price:Sx}}` renderer behind the same helper (phase 2), so keep its interface narrow. Catalogue names contain "&" (e.g. S2); the site uses the 07 names ("and"), never the catalogue's.

**What to design and build (06 §5, 07 §2–§4, PRD WEB-HOME, WEB-SVC-01…06, WEB-G-06, -07, -13…-16):**
- Home sections as components (`src/components/home/*` or a `sections/` folder, your call), with copy in `src/content/` (Markdown or typed content, per CLAUDE.md "Content"), not inline in markup.
- The service-page template as one layout plus section components, fed by structured content for S9 (front-matter or a typed object), so phase 2 only adds content for the other 13.
- **FAQ:** an accessible disclosure list (`<details>`/`<summary>` or buttons with `aria-expanded`); the visible text is the single source for the later `FAQPage` JSON-LD (M2.5), so keep question/answer as data.
- **Currency:** every price block shows `CurrencyNote` once per section that has prices; **fix the first-visit ₹ → $ layout shift** (M2.1 follow-up): stack both amounts in one cell and hide the inactive one with `visibility: hidden` (or equivalent) so the swap can't move anything.
- **One `h1` per page**; each section an `h2`; empty sections omitted (WEB-SVC-02).
- **LCP is text** (the hero heading): no hero image. Motion only where it explains something, ≤ 200 ms, none with reduced motion, nothing loops (WEB-G-15).
- CTA labels and targets exactly as 07 §2.3. "Book a Discovery Sprint" goes to `site.discoveryHref` (as in the header) until the quote form exists (M2.4).

**Rules:** tokens only from `packages/ui` (generated brand files, never hand-drawn logos; the wordmark never in a live font; arrows as icons, not "→"); plain CSS with token custom properties, no new packages (stop and report if one seems needed: it's an owner go-ahead); WCAG 2.2 AA, 44 px targets, text ≥ 12 px and body ≥ 16 px; JS ≤ 50 KB gzipped per page (the home page should need little or none beyond the shell's); English (India/UK spelling), "and" never "&" in page text, no banned phrases (07 §1.3), no "$" alone on a switch (codes INR/USD). The owner's taste: flat ink/verdigris brand geometry, nothing soft, 3D or stock-tech; the bar is 10/10. Use the brand geometry (the 45° cut, the T bar) sparingly and on purpose, as in M2.1.
