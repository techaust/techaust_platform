## Lead decisions (from the analyst's draft; docs/13)
- **LD1** subpath `@techaust/core/tax`, not re-exported from the root; no zod inside; errors are codes only.
- **LD2** the document discount is taken on the net after line discounts and allocated by largest remainder.
- **LD3** for registered clients the GSTIN's state is the place of supply; a different record state is a warning.
- **LD4** no state on an unregistered client is an error (owner 2026-10-25); docs/04 ADM-INV-05 and docs/05 §10 corrected to match.
- **LD5** instalments are floored to the unit and the last takes the remainder (half-up can make the last negative: ₹5 at 30/30/30/10); docs/05 §10 corrected, and its words line follows the decided style ("… and Fifty Paise Only").
- **LD6** the inclusive split works per SAC/rate group (≤ 10), with the largest taxable that fits.
- **LD7** credit notes: per-head caps; a fully credited line takes its remaining tax; the final CN's total equals the remaining total.
- **LD8** USD: INR taxable converted at document level then allocated to lines; tax computed on INR; a CN uses the original's rate.
- **LD9** caps: 100 lines, 24 schedule steps, 10 groups, total ≤ ₹99,99,99,999.
- **LD10** the LUT check reads a list (`lutsOf()`); the hard block and the `tax.luts` list setting are M5.2's.
- **LD11** per-document export-mode override.
- **LD12** the M3.3 follow-ups labelled "M4.2" (`contactId` in `RecipientSnapshot`, keeping `CONTACT_ON_ISSUED_DOCUMENT_SQL` current) and M3.2's stage automation move to M4.3.

### What to build: pure logic in `packages/core/src/tax/`; no I/O, no zod
0. **Layout.** `types.ts`, `supply.ts`, `lines.ts`, `totals.ts` (shared assembly and round-off), `document.ts`, `schedule.ts`, `inclusive.ts`, `credit.ts`, `index.ts`. Subpath export `"./tax": "./src/tax/index.ts"` in `packages/core/package.json`; **not** re-exported from `src/index.ts` (bundle size; it would clash with `clients.ts`'s `TaxWarning`); update that file's header comment.
   - Amounts are safe-integer minor units (`number`), the currency at document level. Every product and quotient in `bigint` through `divRoundHalfUp`; results back through a safe-integer check. Rates in bp, quantities in milli-units, FX in INR micros per USD.
   - Every public function returns `TaxResult<T> = { ok: true; value: T; warnings: TaxWarning[] } | { ok: false; errors: TaxIssue[] }`, `TaxIssue = { code: TaxErrorCode; path: (string | number)[] }`. Codes only, no words (M4.3 maps them to copy).
   - **Never throws** for any input of the declared types (NaN, Infinity, unsafe integers are errors). Validation collects every error before any maths.
1. **Context (settings as input, never constants).** `TaxContext = { tax: Settings["tax"]; supplierStateCode: StateCode /* company.stateCode */; luts: readonly { fy: string; arn: string }[] }`. `lutsOf(tax)` maps today's single `tax.lut` to a list of 0 or 1. Nothing in `src/tax` may contain `SUPPLIER_STATE_CODE`, `1800` or `"19"` (a test greps for them).
2. **Supply and place of supply: `determineSupply(recipient, ctx, opts)`.** The recipient is `TaxInput` from `clients.ts`, validated with `clientTaxCheck` (its error codes passed through unchanged).
   - **Registered:** POS = the **GSTIN's state** (s.12(2)(a) IGST); a different record state adds warning `gstin_state_mismatch`.
   - **Unregistered:** POS = `stateCode` (s.12(2)(b)); missing → error `state_required`.
   - **Overseas** (country ≠ IN): export (s.2(6), s.13(2) IGST): `export_lut` or `export_igst` from `opts.exportMode ?? ctx.tax.exportMode`; POS code `EXPORT_PLACE_OF_SUPPLY` ("96"); an INR document adds warning `export_in_inr`.
   - **Domestic:** POS = `ctx.supplierStateCode` → `intra`, else `inter`.
   - **`opts.placeOfSupplyOverride = { code, reason }`:** domestic only (`pos_override_not_domestic`); a known state (`pos_override_invalid_state`); reason 1–500 characters trimmed (`pos_override_reason_required`); adds warning `pos_overridden` (the caller writes the audit row).
   - **LUT warning:** for `export_lut`, no `luts` entry whose `fy` equals `fyOfDate(documentDate).token` → warning `lut_missing_for_fy` (the hard block is M5.2's).
   - **Output:** `Supply = { type: "intra" | "inter" | "export_lut" | "export_igst"; placeOfSupplyCode: StateCode | "96"; supplierStateCode }` (strings exactly `SUPPLY_TYPES`).
3. **Lines.** `LineInput = { sac: string | null; qtyMilli; rateMinor; gstRateBp?; discount?: { kind: "fixed"; minor } | { kind: "percent"; bp } | null }`.
   - Validation: 1–100 lines (`no_lines`, `too_many_lines`); `qtyMilli` ≥ 1 (`qty_invalid`); `rateMinor` ≥ 0 (`rate_invalid`); `gstRateBp` 0–10,000 (`gst_rate_invalid`), missing → `ctx.tax.defaultRateBp`; with `allowLineOverride` false any other rate is `rate_override_not_allowed`; `sac` `/^\d{6}$/` or null (`sac_invalid`), null adds warning `sac_missing`; fixed discount ≥ 0, percent 0–10,000 bp (`discount_invalid`); above the gross → `discount_exceeds_line`.
   - Per line: `gross = divRoundHalfUp(qtyMilli × rateMinor, 1000)`; `lineDiscount` = the fixed amount or `divRoundHalfUp(gross × bp, 10000)`; `net = gross − lineDiscount`.
4. **Document discount** (same shape as a line discount). Base **Σ net** after line discounts; percent `D = divRoundHalfUp(Σnet × bp, 10000)`; `D > Σnet` → `document_discount_exceeds_subtotal`. Allocate with `money.allocate(D, nets)` (largest remainder, ties to the earliest line; shares sum to D); skip when D = 0 (`allocate` throws on all-zero weights). `taxable_l = net_l − share_l`. Pre-tax (s.15(3)(a) CGST; VERIFY WITH CA).
5. **Tax per line per head** (G-10; ADM-INV-05), each head rounded separately. `intra`: `cgst = sgst = divRoundHalfUp(taxable × rateBp, 20000)` (never 18 % then split). `inter`, `export_igst`: `igst = divRoundHalfUp(taxable × rateBp, 10000)`. `export_lut`: 0. Line output: `{ index, sac, grossMinor, lineDiscountMinor, documentDiscountMinor, discountMinor, taxableMinor, gstRateBp, effectiveRateBp (0 under LUT), cgstMinor, sgstMinor, igstMinor, lineTotalMinor, inr }`.
6. **Totals and round-off (`totals.ts`, shared by 7, 9, 10).**
   - `subtotalMinor = Σgross`; `discountMinor = Σ line discounts + D`; taxable and each head = Σ lines; `preRound = taxable + taxes`.
   - Unit 100 when `currency === "INR" && tax.rounding.totalInr === "nearest_rupee"`, else 1 (USD `"none"`). `total = divRoundHalfUp(preRound, unit) × unit`; `roundOffMinor = total − preRound` (INR −49…+50; USD 0).
   - Optional `targetTotalMinor` (only items 9 and 10): `roundOff = target − preRound`, |roundOff| ≤ 9,999 (IRP band ±99.99, VERIFY WITH CA) else `target_out_of_band`; INR with rounding on: a multiple of 100 (`target_not_whole_unit`).
   - `summary`: rows `{ sac, gstRateBp, taxableMinor, cgstMinor, sgstMinor, igstMinor }` grouped by (sac, rate), first-appearance order (PDF tax summary, GSTR-1 HSN).
   - `words = amountInWords(total)`; above `MAX_WORDS × 100 + 99` → `total_too_large` (checked first: `words.ts` throws); any intermediate outside the safe range → `amount_out_of_range`.
   - B2C: INR, unregistered recipient, total ≥ `tax.b2cDetailsThresholdInrMinor` → warning `b2c_details_required`.
7. **`computeDocument(input, ctx)`.** Input `{ currency; documentDate: CalendarDate; recipient?: TaxInput; supply?: Supply; placeOfSupplyOverride?; exportMode?; lines; documentDiscount?; fx?: { rateMicros } | null }`. Exactly one of `recipient`/`supply` (`recipient_or_supply_required`; a fixed supply is for CN/DN and estimate→invoice). Invalid date → `date_invalid`. Output `ComputedDocument = { currency, supply, lines, summary, subtotalMinor, discountMinor, taxableMinor, cgstMinor, sgstMinor, igstMinor, roundOffMinor, totalMinor, words, inr }` (camelCase of the `documents` / `document_lines` columns).
8. **USD and INR (ADM-INV-08, Rule 34(2); VERIFY WITH CA).** `fx` on INR → `fx_not_applicable`; `rateMicros` ≥ 1 (`fx_invalid`). USD without `fx` → `inr: null` (M5.2 requires it at issue). With `fx`: `inr.taxableMinor = divRoundHalfUp(taxableCents × rateMicros, 1_000_000)`, allocated to lines by `allocate` (weights = line taxable); INR tax per line per head on the line's INR taxable at its effective rate; `inr.roundOffMinor = divRoundHalfUp(roundOffCents × rateMicros, 1_000_000)`; `inr.totalMinor = taxable + taxes + roundOff` (→ `totalInrMinor`). USD never rounded to whole dollars.
9. **Schedules: `computeSchedule(totalMinor, currency, steps, ctx)`** (ADM-PROP-03, Q-P3-6). Steps `{ label, trigger: ScheduleTrigger, pctBp }[]` (percent) or `{ label, trigger, amountMinor? }[]` (amount: all but the last have an amount; the last is the remainder). Mixed → `schedule_mixed_kinds`; 1–24 steps (`schedule_empty`, `schedule_too_many`); invalid step → `schedule_step_invalid`. Unit 100 for INR with rounding on, else 1. Percent: Σbp = 10,000 (`schedule_pct_sum`); each but the last `floor(total × bp / 10000 / unit) × unit`; the last = total − others. Amount: multiples of the unit (`schedule_amount_not_whole_unit`); Σ ≤ total (`schedule_exceeds_total`); display `pctBp = divRoundHalfUp(amount × 10000, total)`, last = 10,000 − others. A 0 instalment → warning `schedule_zero_instalment`. Output `{ label, trigger, pctBp, amountMinor }[]` (→ `payment_schedules`).
10. **Inclusive split: `splitInclusive(grossMinor, groups, supply, currency, fx, ctx)`** (M4.5 first-instalment draft, ADM-PROP-09; M5.2 ADM-INV-10). `groups = { sac, gstRateBp, weightMinor }[]` (normally the source's `summary`, weight = taxable + taxes); 1–10 (`no_groups`, `too_many_groups`); weights ≥ 0, not all 0 (`group_weight_invalid`); gross ≥ 0 (`gross_invalid`), INR with rounding on a whole rupee (`gross_not_whole_unit`). Allocate G across groups; per group the **largest T with T + tax(T) ≤ G_g** (start `floor(G_g × 10000 / (10000 + rate)) + 3`, step down while S(T) > G_g). Output one `LineInput` per group (`qtyMilli 1000`, `rateMinor T`, no discount) plus a `ComputedDocument` with `targetTotalMinor = G`; round-off = G − ΣS (INR 0–20 paise; USD 0–2 cents, warning `inclusive_residual`, VERIFY WITH CA). Invariant: for INR, `computeDocument` on the returned lines gives total G.
11. **Credit notes: `creditNote(original: ComputedDocument, credited, request, ctx)`** (ADM-INV-11). `credited` per original line `{ taxableMinor, cgstMinor, sgstMinor, igstMinor }` plus `creditedTotalMinor`; length mismatch → `credit_shape_mismatch`. `request`: `{ kind: "full" }` | `{ kind: "lines", lines: { line, taxableMinor }[] }` (`credit_line_invalid`) | `{ kind: "amount", taxableMinor }` (allocated over the remaining taxable). Zero → `credit_empty`. Per line: above the remaining taxable → `exceeds_creditable`; equal → each head takes **the remaining tax exactly**; else computed at the line rate (item 5) and **clamped** to that head's remainder. Supply and FX always the original's (VERIFY WITH CA). **Final CN** (nothing left on any line): `targetTotalMinor = original.totalMinor − creditedTotalMinor`; otherwise the normal round-off. A debit note is `computeDocument` with `supply: original.supply` (its FX is M5.3's).
12. **No-floats and coverage.** Add every `src/tax/*.ts` to `MONEY_FILES` (`packages/core/test/no-floats.test.ts:9-17`); a per-glob threshold `src/tax/**` at 100 % branches/lines/functions/statements in `packages/core/vitest.config.ts` (check the Vitest 4.1 glob syntax with Context7); core overall ≥ 90 %.

### Decisions I took (please check; 1 to 4 deviate from the brief's wording)
1. **`ComputedDocument` gains `fxRateMicros: number | null`.** A credit note must use the original's rate and `creditNote` takes no rate argument; it is also the `documents.fx_rate_micros` column.
2. **Shown percentages in amount-mode schedules are cumulative roundings** (a step's share = round(running total x 10,000 / total) minus the previous one; the last is 10,000 minus the others by construction). The brief's "round each, last = 10,000 minus the others" can drift or go negative. G20 gives the same numbers (4,237 / 5,763). A total of 0 shows 0 and 10,000 on the last.
3. **`summary` rows group by the line's stored `gstRateBp`, not the effective rate.** Under LUT a row shows 18 % with tax 0; the effective rate is on each line. Reason: M4.5 feeds the summary to `splitInclusive`, and a group rate of 0 would fail `rate_override_not_allowed` when overrides are off.
4. **`inclusive_residual` is raised whenever the round-off is not 0, INR or USD** (the brief names USD only).
5. `guard` is a catch-all: after validation the only throws left are the overflow checks, so any throw becomes `amount_out_of_range`. This keeps "never throws" at 100 % coverage without an unreachable re-throw; the cost is that a future bug that throws would show as that code (the fuzz and property tests are the safety net).
6. New codes beyond the brief: `currency_invalid` (computeDocument, splitInclusive, computeSchedule) and `total_invalid` (computeSchedule). `credit_shape_mismatch` is also used when the stored "credited" figures are inconsistent (more than the original on a line or head, not whole numbers, or `creditedTotalMinor` outside 0..original total); an unknown request kind and a bad `amount` are `credit_line_invalid`; a negative or non-integer target is `target_out_of_band`.
7. The document discount is judged only once the lines are valid (otherwise a line discount over its line also gave a spurious `document_discount_exceeds_subtotal`).
8. A mixed schedule reports `schedule_mixed_kinds` once, not one `schedule_step_invalid` per step.
9. With `supply` given, `computeDocument` ignores `exportMode` and `placeOfSupplyOverride` (they apply to `recipient` only).
10. Credit-note shapes: `request.lines[].line` is the position in the original's `lines` (the engine's `index`); the note contains only the lines credited now, with `index` = the original's; no B2C warning (no recipient); the INR view is recomputed on the note's own taxable at the original's rate, so the INR figures of several notes may differ from the original's by a few paise (VERIFY WITH CA).
11. `SUPPLY_TYPES` is duplicated in core (core cannot import `@techaust/db`); M4.3 could add a db test tying the two lists.
12. A settings branch the schema cannot reach today (`rounding.totalInr` other than `nearest_rupee`) is tested with a cast.
