## Analyst's tuning analysis (2026-10-17; checked by the lead)

**Main finding:** our own code is cheap. With a fake in-memory D1, the whole `totp` route costs p50 0.28 ms / p99 1.5 ms warm (Node, owner's PC, relative only). On staging, CPU rises with the number of **D1 calls per route**: salt and me make 1 call (≈ 1 ms), login 2 (≈ 2 ms), totp 4 (≈ 4 ms). Each D1 call runs binding JS inside the isolate (JSON, an internal fetch, result mapping), which counts as our CPU. The per-request `importKey` suspicion is ruled out: both keys are cached per isolate (`packages/auth/src/crypto.ts:44-76`).

Measured locally (warm / first call in a fresh process): zod parse 0.003 / 0.7–1.4 ms; SHA-256 0.03 / 0.2–0.5; HMAC 0.04 / 0.3–0.5; AES-GCM decrypt 0.05 / 3.6 (Node's OpenSSL; workerd not checked); HOTP 0.06 / 0.5; GC ≈ 0.5 ms on about 1 request in 140. First-call costs (router and zod set-up, first crypto use) add 2.5–8.6 ms locally.

Hypotheses: **H1** each D1 call costs CPU (explains the p50s and the bimodal totp histogram; medium confidence). **H2** cold or barely-used isolates cause the 12–16 ms spikes (low-to-medium; Workers Logs has no isolate ID). **H3** GC and noise (≈ 1 ms, not 16).

Ranked fixes (no schema change, no security change):
1. **totp 4 D1 calls → 2:** the login challenge carries the lockout key (`ak`, HMAC-signed, so it can't be forged); one joined read of user + attempts; the success DELETE moves into the `startSession` batch (`… AND changes() = 1`). Expected ≈ 1.5–2 ms.
2. **login 2 reads → 1:** one joined read that always returns one row; unknown emails still do the fake-salt HMAC. Expected ≈ 0.7–1 ms.
3. Named columns instead of `SELECT *` on the hot paths (small).
4. A diagnostic log line per auth request `{ev, r, s, iso, n}` (random per-isolate ID and request count; no personal data) to tell H1 from H2 in the re-run.
5. `"sideEffects": false` in `packages/core/package.json` (cold start only, unverified).

Rejected: caching decrypted TOTP secrets (a security change), KV counters (new binding, 1,000 writes/day on Free), replacing zod or the HOTP code (µs savings), `waitUntil` for `fail()` (still charged).

Gate outlook: **login likely** passes (shifts ≈ 1 ms). **totp uncertain**: about 7–8 ms p99 if H1 explains the tail; the spikes stay if H2 does. If it still fails, the analyst's view is the **$5 plan**, not Access + simpler auth, because every later admin route makes 2–5 D1 calls too.
