### Step 2a: builder (Sonnet 5.5, medium)
**First step:** load `cloudflare:web-perf` (build checks, HTML output); `cloudflare:workers-best-practices` only if you touch `src/worker.ts` (you shouldn't). List the skills in the report.

Data, build checks and machine files only; no page markup or CSS beyond what an endpoint needs.
1. **Blog collection:** an Astro content collection (built-in loader, no new packages) at `apps/web/src/content/blog/*.md`, zod front-matter: `title`, `description`, `date`, `updated` (optional), `tags`, `draft` (default true), `relatedServices` (catalogue codes, checked against the catalogue), `faq` (optional list). Drafts are excluded from every route and from RSS. Helpers: published posts newest first, reading time (words ÷ 200, rounded up), headings for a ToC. Add one test fixture post, never a real post.
2. **`/rss.xml`:** a static endpoint written by hand (RSS 2.0, no package): channel title, link, description, `atom:link self`, `language en-IN`; one `item` per published post (title, link, guid, `pubDate` RFC 822, description); XML-escaped. With no published posts it is a valid empty channel. A test parses it.
3. **`/.well-known/security.txt`:** a static endpoint from 07-A §6: Contact `mailto:security@techaust.com`, `Expires` from a configured date in `src/config/site.ts` (`securityTxtExpires`, ISO 8601, set to one year from today), Preferred-Languages, Policy and Canonical on `https://techaust.com/…`. The dist check fails if `Expires` is in the past or more than 366 days away, or if any of the four required fields is missing.
4. **Legal page data:** front-matter (or typed fields) per legal page and `/security`: `version` (starts `0.1`), `effective` (date), `changes` (list of {version, date, note}). A schema check fails the build if a legal page lacks them. The pages show "Version 0.1 · Effective <date>" and a "Changes" section (the designer's step); 07-A's `{{effective_date}}` comes from here.
5. **`{{terms:…}}` tokens** in `lib/tokens.ts`: `{{terms:small_job_threshold}}` renders the settings default `smallJobThreshold` (₹1,00,000 in INR, $2,000 in USD, through the same currency pair as prices, whole units). Read the default from `@techaust/core` (`schemas/settings.ts`) or the snapshot's payment terms when present; an unknown `terms:` key fails the build.
6. **Placeholder tokens** for the legal pages: `{{postal_address}}` renders `site.postalAddress` (new, empty, OWNER) or, while empty, a visible labelled placeholder.
7. **Work data:** a `caseStudies` collection (`src/content/work/*.md`, no entries yet) with front-matter (`title`, `industry`, `size`, `region`, `problem`, `outcome`, `stack`, `verified`, `draft`). The build fails on a non-draft case study without `verified: true` (WEB-WORK).
8. **Link checker:** extend `scripts/web-dist-checks.mjs` (or a new script it calls): every internal `href` and `src` in `dist/**/*.html` resolves to a built file, and every `#fragment` to an `id` on that page; allow-list file for routes another milestone owns (`/contact`, `/get-a-quote`, each with a reason and the milestone), external links are not fetched.
9. **Pre-production check:** `scripts/check-prod-readiness.mjs`, run by `.github/workflows/deploy-prod.yml` before deploying (never by CI or staging), fails while any of these is true: `site.postalAddress`, `site.linkedinFounder`, the founder headshot or bio is empty; `site.aliasesConfirmed` (new, false) is false; a built page contains the `Placeholder` component's marker; `X-Robots-Tag: noindex` is still set for production. Each failure line says what the owner must supply. Unit-test it.
10. **Tests (Vitest, Node):** front-matter schemas (a draft is excluded; a bad `relatedServices` code fails), RSS (valid XML, escaping, empty channel), security.txt (fields, Expires window), `{{terms:…}}` in both currencies and the unknown-key failure, the link checker (a broken link and a broken fragment in a fixture), the case-study `verified` rule, the readiness check.

**Done:** `pnpm check` and `pnpm test` green through `bash tools/heavy.sh`; commit; push; append "Builder report" here; stop.
