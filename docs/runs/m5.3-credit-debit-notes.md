## Findings in the M5.1/M5.2 code that shape this brief (analyst, at m52-b fc24aaf)
1. Voiding a parent once an **issued** note exists is blocked three times (trigger 0038 `documents_invoice_status_flow` `triggers.ts:635`; void SQL `invoices.ts:1006-1011`; core `voidBlockers` `invoices.ts:451-462`). Gaps: a note **draft** doesn't block a void; `documents_parent_check_*` fires only on INSERT or UPDATE OF `parent_id, type, client_id` (`triggers.ts:669-670`), not on the freeze, so a draft whose parent was voided later would issue unless the freeze checks the parent; the void route accepts notes (its type list is all of `INVOICE_FLOW_TYPES`, `invoice-model.ts:101`).
2. `issueBlockers` skips codes whose checklist item doesn't apply to the type (`invoices.ts:360-366`); for a credit note almost all would vanish: notes need their own `noteBlockers`.
3. The freeze sets `balance_minor = total_minor` and a due date for every type (`issue.ts:289-292`): a credit note would show overdue and be chased by M5.4.
4. `header_extras` (frozen JSON, freeze `?28`, unused on drafts) can carry the note's request, reason and parent facts: no new frozen column, no recreated freeze trigger.
5. `FROZEN_COLUMNS_0040` was pinned with `ims_status` in mind (`triggers.ts:676-687`); `ims_status` goes into the live `MUTABLE_AFTER_FREEZE` (`:32-43`).
6. `tax.creditNoteCutoff {month: 11, day: 30}` exists (`schemas/settings.ts:209, :436`); the annual-return date doesn't (it is per FY, so a list).
7. M5.5a's `NoteParent = {number, issueDate, supplyType, recipientStatus, placeOfSupplyCode, totalInrMinor}` (`packages/core/src/gst/types.ts:31-38`) is what a note must freeze (Worker code can't import `@techaust/core/gst`).
8. `creditNote`'s amount request is a **taxable** value (`credit.ts:63, :103-118`) while 07-T §3 says "GST included"; a tax-only debit note can't be expressed (tax is always taxable × rate).
9. The envelope already uses "note" for the export note (`invoice-envelope.ts:98, :225`): the new key is `noteOf`.
10. The lead's quoted line "a credit note against an anonymised client's invoice is a legal correction" was not found in any branch's docs; Q34 treats it as open.

## Lead decisions (docs/13, 2026-10-27)
- **LD38** Notes are invoice-family drafts made from an issued parent (`POST /invoices/:id/credit-note`, `/debit-note`), issued through the M5.1 issue / request / approve pipeline (Owner step-up, Staff requests); one open draft per parent and type (partial unique index).
- **LD39** The note's request, reason and parent facts live in `header_extras.noteOf`; the only new `documents` column is `ims_status`; the seal gains `noteOf` only on notes; the key is `noteOf`, not `note`.
- **LD40** The creditable cap: per line and head in core `creditNote`; `CreditedSoFar` summed in SQL with `json_each`; the freeze holds the total cap, the parent's `updated_at` and `credited_minor`, and the deadline; trigger 0042 re-checks totals and heads.
- **LD41** The parent's ledger is recomputed (not incremented) in the same batch; a CN has balance 0 and no due date; the milestone stays `invoiced`; `refundDueMinor` derived only.
- **LD42** A debit note is its own payable (Q30); the parent is unchanged; the lead updates docs/05 §9.2 :523.
- **LD43** A DN = `computeDocument` with the parent's supply, export route and FX, `trustRates` set by the server; lines from the parent's lines; no LUT or B2C blocker.
- **LD44** CN amounts: amount mode GST-inclusive (`creditForGross`, total ≤ the amount typed); line mode taxable ("before GST"; 07-T §3's line hint reworded); full = everything left; stored `takes` recomputed as a lines request at issue.
- **LD45** The deadline is `creditNoteDeadline` over the supply FY (Q32), `tax.creditNoteCutoff` and the new `tax.annualReturnsFiled` list (G-11's `annualReturnFiledAt`, per FY), bound into the freeze; drafts past it are refused too.
- **LD46** IMS: `ims_status` by ADD COLUMN without a schema CHECK, values by trigger; mutable after the freeze; set by the freeze from the parent's frozen GST status; pending → accepted or rejected once; route `invoices.ims` (Owner, Q36).
- **LD47** Notes are never voided (Q31); a parent's void deletes its open note drafts.
- **LD48** No notes for an anonymised client (Q34).
- **LD49** Closes the M4.2 follow-up: notes raise no LUT or B2C warnings (supply, rate and recipient from the parent's frozen snapshot).
- **LD50** Note blockers have their own `NOTE_BLOCKER_CODES`.
- **LD51** At most 20 issued notes of each kind per invoice; 409 `notes_limit`.
- **LD52** A note's recipient = the parent's frozen legal identity plus the note's own live contact; issuer from current settings; a CN has no bank block and no footer terms, a DN has both.
- **LD53** For M5.5: `noteOf.parent` holds exactly M5.5a's `NoteParent` facts plus id, type, fy, totalMinor; the cdnr/cdnur section is computed at export.
- **LD54** Jobs refuses a CN or DN PDF whose HTML lacks the parent number as one text node.
