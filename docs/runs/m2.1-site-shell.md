## Phase 1: design preview (designer, Opus 5.5 high)
**Goal:** the owner sees and approves the look of the site shell before it's built for real.

**Branch:** `feat/m2.1-site-shell` from `main`, own worktree. The preview is built as real Astro components in `apps/web` (so an approved preview becomes the start of the build), on preview pages only.

**Pages (preview only, `noindex`):**
- `/preview/shell`: the full shell around a labelled sample page body ("Sample content — not final copy").
- `/preview/menus`: Services and Industries menus open; the mobile menu open (separate screenshot states are fine).
- `/preview/components`: header states (top / scrolled sticky), ₹/$ toggle, theme toggle (system/light/dark), CTA button variants, the footer, the consent banner and preferences dialog (shown here even though the build hides the banner), skip link, focus states, a 404 sample.

**What to design and build (06 §5.2, 07 §2.1–2.3, PRD WEB-G-03…06, -08, -15, -16, -18):**
- `SiteHeader` ⚡: logo (generated lockup by width, `aria-label="TecHaust Technologies – home"`), nav Services ▾ · Industries ▾ · Pricing · Work · About · Contact, grouped Services menu exactly as 07 §2.1 (Advise / Build / Automate / Connect / Run + "All services"), Industries menu (3), ₹/$ toggle ("Show prices in"), theme toggle ("Theme: system/light/dark"), CTA "Book a Discovery Sprint". Disclosure buttons (`aria-expanded`), Esc closes and returns focus; works without JS via `<details>`; mobile (< 768 px) full-screen menu dialog with a focus trap. Sticky after scroll, no hide-on-scroll.
- `SiteFooter`: brand line, columns (Services, Industries, Company, Help), contact block, social (placeholders), legal row with © year. **No GSTIN, no proprietor name, no `@techaustsocial`.**
- `ThemeToggle` ⚡ with an inline head script (< 1 KB) so the first paint has the right theme; `CurrencyToggle` ⚡ (radio-group semantics; both prices in the HTML, CSS shows the active one; a sample `PriceTag` on the components page using a clearly fake sample amount labelled "Sample").
- `CookieBanner` ⚡ + preferences dialog per 06 §5.2 (bottom sheet, equal-weight buttons, doesn't cover the hero CTA at 375 px).
- `Button`/`ButtonLink`, `Logo`, skip link, `Notice` (illustrative variant) as needed by the shell.
- A base layout (`en-IN`, landmarks, meta slots for title/description/canonical/OG used later by M2.5).

**Rules:** tokens only from `packages/ui` (`@techaust/ui/tokens.css`, `fonts.css`, generated brand files; never hand-drawn logos; the wordmark never in a live font; arrows as icons); plain CSS with the token custom properties (no new packages — if Tailwind's Vite plugin or anything else seems needed, stop and report: it's an owner go-ahead); WCAG 2.2 AA, 44 px targets, text ≥ 12 px / body ≥ 16 px, reduced motion (≤ 200 ms, nothing loops); JS budget ≤ 50 KB gzipped per page (islands tiny); English (India/UK spelling); no banned phrases (07 §1.3). The owner's taste: flat ink/verdigris brand geometry; generic soft/3D/stock-tech looks are rejected.

**Screenshots** (`.logs/m2.1-preview/`, git-ignored): each preview page at 375, 768, 1280 and 1920 px, light and dark; menus open (desktop and mobile); the scrolled sticky header; keyboard focus on the nav and the mobile menu; the consent banner at 375 px over a hero-like block.

**Checks:** `pnpm check`, `pnpm build` (via `bash tools/heavy.sh --log …`), a scripted a11y pass (44 px, names, contrast, headings, focus) like M1.5/M1.6, JS size per page.

**Stop after the preview:** commit, append "Designer report: preview" here (pages, components, screenshot list, JS sizes, a11y results, every placeholder, deviations, open questions), and stop. The lead sends the screenshots to the owner; **nothing further is built until the owner approves** (a decision row in 13).
