  1. **`documents_invoice_status_flow`** (`BEFORE UPDATE OF status`, `OLD.type` in the invoice family except receipts and vouchers). Allowed moves:
     - draft → issued;
     - issued → void, only when `paid_minor = 0 AND credited_minor = 0` and no frozen document has `parent_id = OLD.id`;

  2. **`documents_void_pairing`:** `NEW.status = 'void'` requires `voided_at` and `void_reason`; a non-void status with `voided_at` aborts; void only when `frozen_at IS NOT NULL`. The CHECK `documents_void_reason` (:237) already pairs the two columns.

  4. **`documents_invoice_type_client_insert` / `_update`** (OF type, client_id): `export_invoice` ⇔ the client is `overseas`; `tax_invoice` ⇒ the client is in India. VERIFY (SEZ not modelled).

     - credit_note / debit_note → tax_invoice / export_invoice;

     - receipt → any invoice-family type (M6).
     
     `parent_id` never changes once frozen (already in the freeze list).

- **Issue handler order:**
  1. One read batch: the bundle (`loadStatements`), the client incl. `updated_at`, the contact, the settings rows with versions, the newest `terms_versions` of kind `invoice` (none → null, allowed), the active bank rows, the pending `issue` approval, the linked milestone.
  2. 404 unless invoice family; 409 `type_not_issuable` unless in `INVOICE_ISSUABLE_TYPES`; frozen → 409 `already_issued` `{number}` (natural idempotency, LD8); `stale_version`; `client_anonymised`.
  3. Recompute with the current client and settings; `contentHash` must equal the stored one, else 409 `content_changed`.
  4. Blockers → 409 `issue_blocked` `{blockers: codes}`.
  5. Seal, then the batch.
  6. On a refused batch (the `issue_result` abort is caught with `refusedWith`), one read picks: `already_issued`, `stale_version`, `numbering_changed` / `settings_changed`, `client_changed`, 403 `step_up_required`, `series_full`. Nothing has been written (counter, audit, milestone).
  7. After the batch: `waitUntil(PDF_QUEUE.send(pdf.snapshot))` through a new `afterIssue` in `document-events.ts`. Answer `{number, issueDate, dueDate, fy}`.
- `issueDate` = the IST day of `Date.now()`; FY from it; series `SERIES_OF[type]`; format `settings.numbering[series]`; `maxNumber(format)`.
- `projects.ts`: the status route sets `delivered_at = coalesce(delivered_at, now)` on the move to `ready_to_bill` (LD12). `invoiced` stays refused there (`:654`); only the issue batch sets it.
- `invoice-model.ts` reuses `resolveLines`, `itemLines`, `computeQuote` (or a sibling that calls the same engine), `taxContext`, `taxInputOf` and `readSettings`. **No copied tax maths.**

- Audit summaries hold ids, numbers, totals and codes only: never a line description, a reason text or personal data.

### Tests (critical ones first)
1. **20 concurrent issues through the route** (the combined `test-app.ts`, owner session with step-up): 20 × 200; numbers `TH/INV/<fy>/0001…0020`, consecutive, no duplicate; 20 audit rows; `next_no = 21`.
   - Variant: 20 parallel where 5 send a stale `expectedUpdatedAt`. Numbers 0001…0015 with no gap, counter 16, no audit rows for the five.
2. **FY rollover** (`vi.useFakeTimers({toFake:["Date"]})`): 31 Mar 2027 23:59:59.999 IST (= 18:29:59.999 UTC) → `TH/INV/2627/000N`; 1 Apr 2027 00:00 IST → `TH/INV/2728/0001`. Each ≤ 16 characters; issue_date and due_date in IST.
3. **Roles:**

   | Caller | Result |
   |---|---|
   | Owner without step-up | 403 `step_up_required`, counter unchanged |
   | Owner with step-up | 200 |
   | Staff | 403 `approval_required` |
   | Sales, accountant (issue) | 403 |
   | Sales (any `/invoices` read) | 403 |
   | Accountant (read) | 200 |
   | Staff request | 201 |
   | Owner approve without step-up | 403 |
   | Owner approve with step-up | issued + approved in one batch |
   | Reject | draft unchanged |
   | Edit after request | approval expired; approving it → 409 `approval_expired`, nothing issued |
   | Two approves in parallel | exactly one issue |
   | Owner issuing directly with a request pending | request closed as approved |
4. **Refusals that leave the counter, audit and milestone unchanged:**
   - stale updatedAt;
   - content changed (the client's state changed after the save);
   - the numbering, company, tax or payment-terms settings version changed between read and batch (bump the row in the test);
   - client updated or anonymised;
   - type `export_invoice` or `proforma` → `type_not_issuable`;
   - each blocker (one test per code);
   - series full (counter at 10,000 with padding 4 → `series_full`);
   - atomicity with an injected failing side statement (the M3.2 pattern): 500 and nothing written, then a normal issue gets the next number.
5. **Freeze:** PATCH and DELETE of an issued invoice → 409; a direct `UPDATE documents SET total_minor …` and an update of a line of an issued invoice abort in the trigger; the existing column-coverage test still passes.
6. **Status flow and void:**
   - table-driven allowed and forbidden moves (trigger and `canMoveInvoiceStatus` agree);
   - void keeps number and number_display, sets status, voided_at and reason;
   - reason required (400);
   - void twice → 409;
   - void with `paid_minor` or `credited_minor` > 0 (set in SQL) → 409;
   - void of a draft → 409;
   - Staff → 403;
   - void → issued aborts;
   - `documentsIssuedSummary` over issued + voided rows: from–to, total, cancelled;
   - `GET /invoices?status=void` lists it.
7. **Triggers:** currency mismatch, type versus client, parent pairs (each allowed pair passes; wrong client, unfrozen parent or wrong type aborts), milestone scope.
8. **Milestone flow:**
   - a draft from a `ready_to_bill` milestone (inclusive split; the total equals the milestone amount for INR);
   - a second draft → 409;
   - issue → `invoiced`, `delivered_at` kept;
   - void → back to `ready_to_bill`, link cleared;
   - delete of the draft → link cleared.
9. **Erase:** the invoice's contact cannot be erased (409 `on_issued_document`); the snapshot carries `contactId` and email.
10. **`sendStatements`** SQL unchanged (snapshot); every existing documents/offers test passes unchanged.
11. **Stage B:**
    - issue enqueues `pdf.snapshot`;
    - the envelope is written once and the render (stub) writes the PDF and its SHA-256;
    - a tampered envelope is refused with a bell;
    - the sweep picks an invoice without a PDF;
    - an anonymised client is skipped;
    - the skeleton HTML contains every Rule 46 field: intra prints CGST 9 % + SGST 9 %, inter prints IGST 18 %; the words; "Tax payable on reverse charge: No"; "ORIGINAL FOR RECIPIENT"; a signature image only when set and verified.
12. **Core:** the validator's first-character rule (property); blocker table; due date; `issueFyOf` at the boundary.
