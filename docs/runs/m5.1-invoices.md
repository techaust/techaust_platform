- **Issue handler order:**
  1. One read batch: the bundle (`loadStatements`), the client incl. `updated_at`, the contact, the settings rows with versions, the newest `terms_versions` of kind `invoice` (none → null, allowed), the active bank rows, the pending `issue` approval, the linked milestone.

  3. Recompute with the current client and settings; `contentHash` must equal the stored one, else 409 `content_changed`.
  4. Blockers → 409 `issue_blocked` `{blockers: codes}`.
  5. Seal, then the batch.
  6. On a refused batch (the `issue_result` abort is caught with `refusedWith`), one read picks: `already_issued`, `stale_version`, `numbering_changed` / `settings_changed`, `client_changed`, 403 `step_up_required`, `series_full`. Nothing has been written (counter, audit, milestone).

3. **Roles:**

   | Caller | Result |
   |---|---|
   | Owner without step-up | 403 `step_up_required`, counter unchanged |
   | Owner with step-up | 200 |
   | Staff | 403 `approval_required` |
   | Sales, accountant (issue) | 403 |

4. **Refusals that leave the counter, audit and milestone unchanged:**
   - stale updatedAt;
   - content changed (the client's state changed after the save);

   - series full (counter at 10,000 with padding 4 → `series_full`);

5. **Freeze:** PATCH and DELETE of an issued invoice → 409; a direct `UPDATE documents SET total_minor …` and an update of a line of an issued invoice abort in the trigger; the existing column-coverage test still passes.

7. **Triggers:** currency mismatch, type versus client, parent pairs (each allowed pair passes; wrong client, unfrozen parent or wrong type aborts), milestone scope.
8. **Milestone flow:**

### Decisions taken
1. **Blocker and void codes follow the lead's 07-R draft** (`line_sac_missing`, `zero_total`, `computed_errors`, `type_not_allowed`, `void_not_allowed` with a `reasons` list, `already_void`, ...), and the bell words are 07-R's (owners: "{requester} asked you to issue an invoice for {client name}."; requester: "Your invoice for {client name} was issued as {number}." and "Your request to issue the invoice for {client name} was rejected.").
2. `INVOICE_SERIES_OF` lives in core (the admin Worker must not import the Drizzle schema); a db test checks it equals `SERIES_OF`.
3. `DraftContent.type` is `string` so an invoice uses the SAME `contentHash`; the hash text for proposals and estimates is unchanged (all their tests pass).
4. `balance_minor = total_minor` is set by the freeze (LD17). The brief's freeze list did not name it; the column is mutable after the freeze, and the overdue rule needs it.
5. The `invoice.issue` audit summary has no number (it is assigned inside the batch, after the audit statement is built); the entity id is the document. `invoice.void` carries the number. In the approve path the batch writes two audit rows: `approval.decide` and `invoice.issue`.
6. A Staff issue request rings the owners' bell but queues NO `approval.notify` email: the jobs consumer reads discount approvals and 07-R's issue variant is phase 2.
7. `SWEEP_SQL` (jobs) lists the same seven types as the widened index: `INDEXED BY` needs the query to imply the index predicate, so without this the sweep would fail. The sweep therefore now also picks invoices; the snapshot consumer skips them as `unsupported_type` until B2.
8. The milestone becomes `invoiced` from `pending` or `ready_to_bill` (the first-instalment draft that "Start project" links sits on a `pending` milestone); a void sets it back to `ready_to_bill` with the link cleared.
9. A void is refused for an anonymised client (`client_anonymised`; the standing rule that such a client takes nothing new). Discarding a draft is not (as for quotes).
10. "Emailed" for Q1 is the existence of a `document_sends` row of the document (M5.4 writes them; none exist now).
11. The update triggers for currency, type and parent act only while the document is not frozen (the freeze trigger keeps its own message for a frozen one); the void pairing acts only on flow types and not on a row that is already void.
12. `milestones_document_scope_insert` and the extra `UPDATE` of the approver's note are small additions to the brief.
13. The issue freeze sets `terms_version_id` from the newest `invoice` terms (none is allowed). No bank account is NOT a blocker in M5.1 (it is the M5.2 checklist's, Q10).
14. The staff PDF retry is open to Staff (the guard's "approval" decision lets it through; the retry is harmless and idempotent).
