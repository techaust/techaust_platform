# M1.5 follow-up: break-glass for the only owner

Tier A (staff auth). Owner decision 2026-10-21 (Q1 of [m1.5-staff-auth](m1.5-staff-auth.md), the analyst's Option 1).

## Brief
**Problem:** `pnpm admin:reset-2fa` (`scripts/reset-2fa.mjs`) refuses to reset the only active owner, because the `staff_users_keep_owner` trigger (migration 0004) forbids taking the last active owner out of "active owner". With one owner today, docs/08 §3.2's break-glass doesn't work.

**Decision:** keep the trigger strict. For the only active owner, the script instead issues a one-time **owner invite for a second email the owner controls**. The owner enrols that new account, then resets or deactivates the lost one from Staff and invites (allowed once two owners exist). No database control is weakened; no trigger bypass of any kind.

**Behaviour (`scripts/reset-2fa.mjs` + `scripts/reset-2fa-sql.mjs`):**
- Unchanged for every case except "the target is the only active owner".
- That case: without `--new-email <address>`, refuse with a clear message that explains the break-glass and shows the exact command with `--new-email`. With it:
  - validate the address like `--email`; refuse if it equals `--email`, or if any `staff_users` row has that email (any status), or if a live unused invite for it already exists;
  - in **one** `wrangler d1 execute --file` run (atomic): insert the `staff_invites` row (role `owner`, `--hours` 1–48, default 48, token SHA-256 as today) and one `audit_log` row, action `user.invite`, actor "system" (as the existing reset audit rows do), summary `{via:"cli", reason:"break-glass"}` plus the lost owner's user **id** (no email, IP or other personal data in the summary);
  - do not touch the lost owner's `staff_users` row, sessions or recovery codes;
  - print the link (fragment `#t=…`, as today) and the next steps: open it, enrol, then in Staff and invites reset or deactivate the old account.
- Header comment and the error texts updated to match.

**Tests:** extend the existing tests of the SQL builders (find them; add to the same suite) for the new statement builder: the exact statements, quoting of hostile emails, role `owner`, expiry from `--hours`, the audit summary keys, and that no statement touches `staff_users`, `staff_sessions` or recovery codes. If the script's argument checks live in `reset-2fa.mjs` only, move them into a pure function the tests can call (refusals: same email, existing user, live invite, missing `--new-email`). Run once by hand against the **local** D1 with a single local owner and show the output.
