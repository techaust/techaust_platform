1. **Fold.** `UPDATE settings … FROM (…)` appends `{fy, arn: normalised, filedOn: null}` to `tax.luts` (or makes the list when it is missing) only when the M5.2 rule (core's former `legacyLutFate`) says `folded`:
   - `lut.arn` and `lut.fy` are JSON strings;
   - no list object has that exact `fy`;
   - the `fy` is 4 ASCII digits naming consecutive years;
   - the ARN, normalised exactly like `normaliseLutArn`, is 1 to 30 of `A-Z0-9`. Normalising means every JS `\s` code point dropped, the 10 code points whose JS `toUpperCase()` is pure A-Z spelled out (ß, ı, ſ, ﬀ to ﬆ), then `upper()`. A NUL or any non-ASCII is refused through `length(CAST(x AS BLOB)) = length(x)`;
   - the list holds fewer than 20.

   A list that is not an array gets nothing. Every JSON function reads `CASE WHEN json_valid(value) THEN value END`, so a non-JSON row can't fail the migration.
2. `json_remove(value, '$.lut')` in every case (a JSON null or garbage too). **`version + 1`** so a tab that is still open gets 409 and reloads. `updated_at` and `updated_by` are left alone, and no audit row is written (see Q2).
